Day 14 – Playwright Configuration & Screenshots 

1. Understanding Manual Screenshot in Playwright Test

🔹 In example.spec.js, I added the following code:

await page.screenshot({
  fullPage: true,
  path: 'full-page.png'
});

🔹 Through this, I understood that page.screenshot() captures the browser screen at that exact moment. By using fullPage: true, the entire scrollable page is captured. The path property allows me to decide where the screenshot will be saved. This screenshot is taken even if the test case passes, and the image file gets saved directly inside my Day14 project folder.


2. Taking Screenshot Automatically Using playwright.config.js

🔹 I modified the configuration file by adding:

use: {
  screenshot: 'only-on-failure',
}

🔹 From this change, I learned that Playwright can automatically capture screenshots when a test fails, without writing any screenshot code inside the test file. This behavior is controlled from the configuration file and is very useful for debugging failed tests.

3. Verifying the Configuration by Failing a Test

🔹 To confirm that the configuration was working, I intentionally made one test case fail. After running the test, I observed that Playwright automatically captured a screenshot of the failed test. This helped me verify that my configuration change was correct.

4. Observing the test-results Folder

🔹 After running the command:

npx playwright test

🔹 I noticed that a new folder named test-results was created automatically. This folder contains the screenshot of the failed test along with other execution evidence generated by Playwright.
